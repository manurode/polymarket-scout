# Scout Lab v2.0 — Guía de Arranque con Datos Reales

## ¿Qué cambió en v2.0?

El dashboard ya no muestra datos estáticos/mock. Ahora el backend expone el estado **real** del sistema:

- **Wallet virtual** con saldo USDC/POL que sube y baja según operaciones.
- **Posiciones abiertas** con mark-to-market en tiempo real (precios simulados + P&L dinámico).
- **Reconciliación WS** real: mercados en estado CLEAN vs RECONCILING.
- **Spoofing scores** reales desde el SpoofDetector.
- **Heartbeats** con latencias reales del WebSocket manager.
- **Rankings de estrategias** con Sortino, win-rate y trades reales (actualizados por paper trading).
- **Uptime** real del servidor.

El frontend en `web/` se conectará a `http://localhost:8000` y mostrará datos simulados si no hay orchestrator.

#### B) Modo Producción Real (orchestrator + dashboard)

Crea un script de arranque que inyecte el orchestrator:

```python
# run_real.py
import asyncio
from dashboard.server import create_app
from src.orchestrator import ScoutOrchestrator
import uvicorn

async def main():
    config = {
        "selection": {"top_n": 50},
        "auto_trader": {
            "enabled_strategies": [
                "momentum_follow", "contrarian", "consensus_breakout",
                "volume_breakout", "market_making", "correlation_arb",
            ]
        },
        "paper_trading": {
            "initial_usdc": 10000.0,
            "initial_pol": 100.0,
        },
    }

    orchestrator = ScoutOrchestrator(config)
    await orchestrator.start()

    app = create_app(orchestrator=orchestrator)

    config_uvicorn = uvicorn.Config(app, host="0.0.0.0", port=8000, log_level="info")
    server = uvicorn.Server(config_uvicorn)
    await server.serve()

if __name__ == "__main__":
    asyncio.run(main())
```

Ejecutar:

```bash
cd /workspace/polymarket-scout
python run_real.py
```

Esto arranca:
1. **Radar loop** — escanea Gamma API cada 60s.
2. **Health check loop** — evalúa degradación cada 10s.
3. **Markout updater** — actualiza toxicidad cada 5s.
4. **Portfolio epoch loop** — avanza épocas del MAB cada 6h.
5. **Paper MTM loop** — mark-to-market de posiciones cada 5s.
6. **Paper auto-close loop** — evalúa TP/SL/tau cada 10s.
7. **Paper signal loop** — genera señales demo cada 30s (mientras haya liquidez y <6 posiciones abiertas).

## ¿Qué verás en el Dashboard?

### Tab SYSTEM
- **Heartbeats**: latencias reales del CLOB WebSocket (ms), Gamma API, Polygon RPC, Redis Bus.
- **Reconciliation Matrix**: progreso real de cuántos mercados están CLEAN vs RECONCILING.
- **Rate Limit Budget**: tokens disponibles por bucket (reconciliation, onboarding, ad-hoc).
- **Degradation Mode**: estado real del sistema (full/minimal) y si puede tradear.
- **Wallet Monitor**: saldo USDC y POL **real** del paper trading (cambia tras cada trade).

### Tab PORTFOLIO
- **Tournament Ranking**: estrategias ordenadas por Sortino. Las columnas `trades` y `win_rate` se actualizan cuando el paper trading cierra posiciones.
- **Capital Allocation**: barras dinámicas de active/frozen/retired basadas en el equity real.
- **Epoch**: número de época real del Multi-Armed Bandit.

### Tab ORACLES
- **Spoofing Heatmap**: scores reales del SpoofDetector para cada mercado trackeado.
- **Whale Tracker**: datos reales del WhaleTracker (alpha whales + flow por mercado).

### Tab RISK
- **Open Positions**: tabla con posiciones del PaperTradingEngine. El `Mark` y `PnL` cambian cada 5 segundos (mark-to-market).
- **Time-Decay Calendar**: barras de tau% con colores de alerta.
- **Correlation Matrix**: simulada (placeholder hasta tener datos reales de correlación).

## Comportamiento del Paper Trading

### Condiciones iniciales
- **USDC**: $10,000 virtuales (free).
- **POL**: 100 virtuales.

### Apertura automática
El `signal loop` abre posiciones cuando:
- Hay menos de 6 posiciones abiertas.
- Hay más de $200 USDC libres.
- El tamaño Kelly calculado es > $50.

### Cierre automático
Una posición se cierra automáticamente cuando:
- **Take Profit**: P&L >= +15%.
- **Stop Loss**: P&L <= -10%.
- **Time-Decay**: tau >= 95%.
- **Expiración**: 72h desde apertura.

### Feedback al PortfolioManager
Cuando una posición se cierra:
1. Se calcula el P&L final.
2. Se actualiza `total_trades` y `winning_trades` de la estrategia.
3. Se recalcula el **Sortino Ratio** con la nueva serie de retornos.
4. En la próxima época, el MAB reasignará capital según el nuevo ranking.

## Notas y Limitaciones

1. **Precios de mark-to-market**: actualmente usan simulación de movimiento browniano (volatilidad 0.2% por tick). Cuando el WebSocket manager tenga libros reales, se cruzarán con el mid-price real.
2. **DOM Chart / Spoof Detail**: siguen siendo visualizaciones de ejemplo. El heatmap de spoofing sí usa datos reales del detector.
3. **Latency Budget**: es un estimado estático de la arquitectura. Para instrumentación real se necesitaría tracing distribuido.
4. **Correlation Matrix**: placeholder. Requiere calcular correlaciones históricas entre mercados.

## Troubleshooting

### `git push` pide SSH key
```bash
# Usar token HTTPS temporal (ya configurado en sesiones previas)
git remote set-url origin "https://manurode:TOKEN@github.com/manurode/polymarket-scout.git"
git push origin main
# Restaurar SSH después
git remote set-url origin git@github.com:manurode/polymarket-scout.git
```

### Frontend no carga datos
- Verifica que el backend está en `http://localhost:8000`.
- Revisa CORS: el servidor permite `localhost:5173` y `localhost:3000`.
- Mira la consola del navegador por errores de red.

### `tsc -b` pasa pero `vite build` falla con rolldown
Es un problema de dependencia nativa de `rolldown` en el contenedor Linux. El código TypeScript es válido. Para producción, construir desde un entorno con las toolchains nativas correctas.
